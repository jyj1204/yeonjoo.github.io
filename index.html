방법론 선택 이유

왜 이 방법을 선택했는가

각 방법은 기법을 써보려고 선택한 게 아닙니다. 그 방법이 아니었으면 잘못된 결론에 도달했을 것이기 때문에 선택했습니다.

✗ 다른 방법 썼다면

일반 KFold → 같은 창고 스냅샷 누출 → 성능 과대평가

✓ 이 방법을 쓴 이유

창고 단위 완전 분리 → 실제 배포 환경 시뮬레이션

✗ 다른 방법 썼다면

상관계수만 → pack r=0.105 '관계 없음' → 핵심 변수 누락

✓ 이 방법을 쓴 이유

비선형 U자형 포착 → 모델 1위 재발견 → 반례 수렴

✗ 다른 방법 썼다면

단순 비교 → hub_spoke +3.69분 → 레이아웃 개선 추진 (고비용 오판)

✓ 이 방법을 쓴 이유

운영 조건 통제 → 효과 소멸(p=0.783) → 레이아웃 X, 운영 O

✗ 다른 방법 썼다면

전체 경향만 → 'idle 높으면 안전' 단순 결론

✓ 이 방법을 쓴 이유

공통 원인: pack 과포화 → U자형 분석과 수렴 → 신뢰도↑
