배경왜 데이터 품질부터 봤는가

RetailRocket 실제 이커머스 로그 데이터(view, addtocart, transaction)를 분석해 낮은 전환율의 원인을 진단하고 추천 모델 및 실험 설계로 연결하는 것이 목표였습니다. 사이트명·상품명·브랜드·가격은 익명화되어 있어 로그, 상품 가용성, 카테고리 정보를 중심으로 분석했습니다.

단순히 추천 모델을 먼저 만드는 대신, 데이터 품질을 진단하고 비정상 트래픽이 퍼널 지표에 어떤 영향을 주는지 먼저 확인한 뒤 모델 비교와 실험 설계를 진행했습니다.

파일내용
events.csv사용자 행동 로그: view, addtocart, transaction
item_properties.csv상품 속성 정보: categoryid, available 등
category_tree.csv카테고리 계층 정보

핵심 질문: 전환율이 낮은 이유는 추천 모델의 문제인가, 아니면 그 이전 단계 — 상품 가용성과 트래픽 품질 — 의 문제인가?

가설 1: 상품 자체의 문제
검증판매 가능 상태(available)와 메타데이터 확인

903개 상품 중 711개(78.7%)는 판매 불가능 상태였고, 120개(13.3%)는 item_properties에 존재하지 않는 상품이었습니다. 판매 가능 상태였던 상품은 72개(8.0%)였습니다.

가설 2: 비정상 트래픽 문제

B · TreatmentCategory-based Recommendation

판매 가능 상품 기준 사용자 관심 카테고리 기반 추천. 사용자의 과거 행동으로 대표 관심 카테고리를 찾고, 해당 카테고리 내 판매 가능 인기 상품을 추천합니다.

Exclusion Rule사전 정의된 제외 규칙

실험 전 정의한 view-heavy 비정상 사용자 규칙 적용.

Main Abnormal Rule:
total_events ≥ 50, transaction = 0, cart_event_ratio ≤ 0.02 (medium 기준)

Stop Rule중단·롤백 기준

구매 전환율 또는 cart-to-transaction rate가 대조군 대비 유의미하게 하락하거나, available=0 상품 노출이 발생하면 중단 또는 롤백합니다.

실험 설계의 핵심: 이번 실험은 UI 디자인 변경이 아니라 추천 로직 변경 실험입니다. A그룹은 안정적인 baseline(판매 가능 상품 기반 인기 추천), B그룹은 관심 카테고리를 반영한 개인화 추천입니다. available=0 상품 제외와 비정상 사용자 제외는 결과를 본 뒤가 아니라 실험 전에 사전 정의해야 결과 해석에 편향이 생기지 않습니다.

Expected Impact오프라인 평가 기반 기대 효과

오프라인 평가에서 available_only_popularity는 기존 popularity 대비 Hit Rate@10, Recall@10, Precision@10이 모두 개선되었습니다. B그룹의 카테고리 기반 추천도 같은 가용성 필터를 적용한 상태에서 개인화 효과를 추가로 검증하는 구조입니다.

낮은 전환율은 단순히 추천 모델 문제만은 아니었습니다. 고조회 무전환 상품의 대부분은 판매 불가능 상태이거나 상품 메타데이터가 누락된 경우였습니다.

view-heavy 비정상 사용자는 전체 사용자 수로는 적지만, view 기반 퍼널 지표를 왜곡할 수 있었습니다. 추천 모델에서는 복잡한 개인화보다 판매 가능 상품 필터를 적용한 popularity 모델이 가장 안정적인 성능을 보였습니다.

따라서 이커머스 추천 시스템이나 A/B 테스트를 설계할 때는 모델 개선 이전에 상품 가용성 관리와 비정상 트래픽 제거 같은 데이터 품질 관리가 먼저 필요합니다.
