Step 2.
원인 가설 검증 — 상품 상태와 사용자 행동

낮은 구매 전환율의 원인을 상품 상태와 사용자 행동, 두 방향에서 검증.

가설 1 "조회는 많은데 안 팔리는 건 상품 자체에 문제가 있는 건 아닐까?"

조회 100회 이상, 장바구니/구매가 0건인 상품 903개의 상태를 확인해 낮은 전환의 원인을 살펴봄.

903개 상품 원인 분류
품절 상품 제거 전/후 성능 비교

살 수 없는 상품을 추천 후보에서 제거했을 때 Precision@10이 어떻게 바뀌는지 확인

✅ 가설 1 검증 결과
903개 상품 중 92%가 품절 또는 상품 정보 미등록 상태.
품절 상품을 추천 후보에서 제거하는 것만으로 Precision@10이 0.005 → 0.006으로 개선.
가설 2 "이상하게 활동하는 사용자가 전체 지표를 왜곡하는 건 아닐까?"

다수의 사용자는 사이트에서 1~2번 정도 행동하고 떠남.
소수의 사용자는 장바구니도 구매도 없이 조회만 수십~수백 번 반복.
이러한 사용자가 조회 수 분모를 부풀려 전환율이 왜곡.

Step 3.
매출 상승 전략 — 추천 알고리즘 비교

정제된 데이터로 5가지 추천 방식 비교

과거 데이터(train)로 추천 후보를 만들고, 이후 기간(test)에 실제 장바구니/구매 상품이 추천 목록에 있었는지로 점수 산출.

5가지 추천 방식, 세 지표로 비교

상위 10개 추천 기준(K=10). 각 지표는 높을수록 좋음.

추천 방식Precision@10Hit Rate@10Recall@10
전체 인기순 (기본)0.0050.0460.024
이상 사용자 제거 + 인기순0.0050.0440.022
판매 가능 + 인기순 K=10 1위0.0060.0510.028
관심 카테고리 기반0.0040.0440.025
함께 본 상품 기반0.0040.0360.018

Precision: 추천 10개 중 정답 비율 · Hit Rate: 하나라도 맞은 사용자 비율 · Recall: 관심 상품 중 추천에 포함된 비율
K=20에서는 관심 카테고리 기반 추천이 Hit Rate와 Recall에서 가장 높았음.

💡 핵심 인사이트
품절 상품을 추천 후보에서 제외하는 것만으로 세 가지 지표가 모두 개선.
상위 노출 영역에는 판매 가능한 인기 상품을, 더 넓은 영역에는 개인 관심사 기반 추천을 쓰는 방법을 추천.
Step 4.
매출 상승 전략 — A/B 테스트 설계

인기순 추천보다 관심 카테고리 추천이 장바구니 행동을 늘릴까?

Step 3에서 판매 가능 + 인기순이 상위 10개 기준으로 가장 좋았음. 이를 기준선으로 두고, 관심 카테고리를 반영한 추천이 실제 사용자에게 더 많은 장바구니 추가를 만드는지 검증하도록 설계.

두 그룹 모두 품절 상품 제외. 비교하는 것은 전체 인기순 추천과 개인 관심 카테고리 추천의 차이.
A그룹 (대조군, 50%)
판매 가능 + 인기순 추천
판매 가능한 상품 중 전체 사용자의 장바구니/구매 이력이 많은 순서로 추천. 오프라인 평가에서 가장 좋은 기준선.
B그룹 (실험군, 50%)
판매 가능 + 관심 카테고리 추천
같은 판매 가능 상품 중 사용자의 과거 행동으로 파악한 관심 카테고리의 인기 상품을 추천.

실험 전에 미리 정해둔 규칙
이상 사용자 제거 기준(중간)을 실험 시작 전 미리 적용. 결과를 보고 나서 기준을 바꾸면 분석이 왜곡될 수 있으므로 시작하기 전에 먼저 정해두는 것이 중요함.

Step 5.
프로젝트 결론 — 분석 결과와 인사이트

프로젝트 결론 및 인사이트

🏷️
가설 1 — 상품 데이터 품질 문제
조회는 많은데 안 팔린 상품 903개의 92%는 품절 또는 상품 정보 미등록 상태. 추천 알고리즘이 아닌 상품 데이터 관리가 우선 과제.
👥
가설 2 — 이상 사용자의 지표 왜곡
이상 사용자 제거 시 전환율이 소폭 개선되지만, 구매 건수 자체의 변화는 미미함. 조회수를 부풀려 지표를 낮게 보이게 만드는 구조.
🎯
핵심 인사이트 — 데이터 품질 우선
모델 고도화 전에 데이터 품질 점검이 우선적으로 필요. '품절 제외' 필터 하나가 Precision@10 기준 가장 효과적인 개선.
프로젝트 주요 성과
  • 가설 1 검증전환 불가 상품 903개 중 92%가 품절 또는 상품 정보 미등록 상태임을 확인 - 데이터 품질 문제로 귀결
  • 가설 2 검증이상 사용자 제거 시 전환율 소폭 상승 (0.84%→0.90%), 구매 건수 자체는 변화 미미
  • 알고리즘 비교5가지 추천 알고리즘 오프라인 평가 — '판매 가능 + 인기순'이 상위 10개 기준 최고 성능
  • A/B 테스트 설계핵심/참고/안전장치 지표 정의, 실험 전 기준 확정, 중단 기준까지 설계
  • 제약 사항실제 A/B 테스트 미실시 (오프라인 시뮬레이션). 실사용 데이터 확보 시 온라인 검증 필요

프로젝트 회고

잘한 점
  • ✓
    가설 기반 분석 접근
    알고리즘부터 개선하지 않고 상품 문제와 사용자 왜곡 두 가설을 먼저 세운 뒤 데이터로 검증하는 순서로 분석
  • ✓
    이상 사용자 기준별 민감도 확인
    엄격/중간/느슨 3단계 기준에 따른 전환율 변화를 비교하고, 후속 분석에는 중간 기준을 적용.
  • ✓
    오프라인 평가 후 A/B 테스트 설계
    알고리즘 비교를 오프라인 시뮬레이션으로 먼저 진행한 뒤, 가드레일 지표, 중단 기준까지 포함한 실험 설계로 이어짐.
  • ✓
    데이터 품질 문제를 먼저 발견
    전환율 저하의 원인이 알고리즘이 아닌 품절 상품 포함이었다는 점을 데이터로 확인하고, 해결 우선순위를 조정할 수 있었음.
아쉬운 점
  • △
    실제 A/B 테스트 미실시
    오프라인 시뮬레이션에서 멈춰 추천 개선이 실제 매출에 얼마나 영향을 줬는지 온라인 검증이 이루어지지 않음.
  • △
    매출 금액 데이터 부재
    구매 건수는 있지만 실제 금액 데이터가 없어 CLV나 매출 기여도 분석으로 연결하지 못함.
  • △
    이상 사용자의 실체 미확인
    봇인지, 내부 사용자인지, 특정 행동 패턴의 일반 사용자인지 확인하지 못해 제거 결정의 근거가 다소 약함.
  • △
    품절 상품 포함 원인 미추적
    왜 품절 상품이 추천에 계속 포함됐는지 시스템 레벨 원인(재고 연동 누락, 업데이트 딜레이 등)을 확인하지 못함.
