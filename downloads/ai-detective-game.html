AI와 함께 AI를 만든 과정

ChatGPT·Claude를 활용해 코드 설계·구현·디버깅 전 과정 진행. Vibe Coding은 단순 코드 생성이 아니라, AI와의 대화를 통해 설계를 함께 발전시키는 방식.

🏗️설계 단계
직면한 문제
GPT API를 어떻게 용의자처럼 말하게 할까?
AI의 역할
프롬프트 엔지니어링 구조 설계 제안. '4개 레이어' 아이디어 도출
결과
역할 정의 + 단서 연동 + 답변 제약 + 채점 프롬프트 분리 구조 확정
⚙️구현 단계
직면한 문제
씬 전환 시 BGM과 단서 추가가 동시에 안 됨
AI의 역할
Promise 체인 기반 switchScene 엔진 구조 제안 및 코드 작성
결과
비동기 씬 전환 엔진 완성. 페이드·BGM·단서·타이머 동기화 달성
🐛디버깅 단계
직면한 문제
AI 용의자가 3번 질문하면 자백해 버리는 문제
AI의 역할
시스템 프롬프트의 답변 제약 레이어 강화 방안 제시
결과
압박 시 화제 전환 패턴 추가. 자백 없이 긴장감 유지 가능
✨개선 단계
직면한 문제
채점 결과가 너무 기계적으로 느껴지는 문제
AI의 역할
채점 기준을 점수 중심 → 서술 피드백 중심으로 재설계 제안
결과
등급 + 구체적 피드백 텍스트 조합. 플레이어 만족도 향상
Vibe Coding에서 배운 것
🧠
AI는 구현보다 설계에 강하다
'이런 기능 만들어줘'보다 '이런 문제를 어떻게 설계해야 할까?'를 물었을 때 더 좋은 결과 도출.
📝
맥락 제공이 핵심이다
코드만 붙여넣는 것보다 '이 프로젝트는 ~이고, 현재 ~문제가 있어'처럼 배경을 설명했을 때 훨씬 정확한 도움 확보.
⚠️
AI가 틀릴 때를 알아야 한다
생성된 코드를 무조건 신뢰하지 않고, 동작 원리를 이해하면서 적용해야 함. 이해 없는 Vibe Coding은 복잡성만 키움.
한계 및 성과

솔직한 평가

GPT API 응답 지연 (1~3초)
심문 중 AI 응답 대기 시간이 몰입을 끊음. 특히 모바일 환경에서 더 두드러짐.
→ 개선 방향스트리밍 응답(SSE) 적용으로 타이핑 효과처럼 실시간 출력하면 체감 속도 개선 가능
API 키 클라이언트 노출 문제
현재 구조는 OpenAI API 키가 config.js에 평문으로 존재. 실서비스라면 심각한 보안 문제.
→ 개선 방향Node.js 백엔드 프록시 서버 추가 → API 키를 서버에서만 관리하도록 구조 변경 필요
토큰 비용 제한 없음
대화가 길어질수록 GPT API 호출 비용이 선형으로 증가. 프로덕션 서비스라면 비용 폭증 가능성 존재.
→ 개선 방향대화 히스토리 요약(summarization) 기법으로 오래된 기록을 압축하여 토큰 절감
AI 답변 일관성 한계
같은 질문에 항상 동일한 반응을 보장하기 어려움. GPT의 확률적 특성상 가끔 시나리오에서 벗어난 답변 발생.
→ 개선 방향temperature 조정 + Few-shot 예시 추가로 일관성 향상 가능. 완전 해결은 어려움.
프로젝트가 증명한 것
✓ 단순 채팅봇 → 맥락 유지 AI 용의자
4레이어 프롬프트 + 대화 히스토리 전달 구조로 달성
✓ 프롬프트 엔지니어링으로 캐릭터 구현 가능
4인의 AI가 각기 다른 알리바이·거짓말 패턴·반응 방식을 가짐
✓ Vibe Coding으로 복잡한 인터랙션 개발 가능
설계·구현·디버깅 전 과정 AI 협업으로 학기 내 완성
