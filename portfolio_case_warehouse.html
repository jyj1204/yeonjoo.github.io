01

결론이 세 번 바뀐 과정

각 단계는 이전 결론을 의심하고 검증하는 방향으로 이어졌습니다. 분석이 깊어질수록 결론이 더 정확해졌습니다.

01 · EDA
idle이 핵심이다
30% 임계점 발견. 배터리 소모→충전 대기→idle 감소 연쇄 구조 확인.
02 · 모델링
EDA가 놓친 변수
pack_utilization 상관계수 0.105 → '관계 없음' 판단했는데 모델 중요도 1위(14.2%).
03 · 경보 규칙
임계값 방식 실패
규칙·ML 모두 Precision ~0.12 상한. 단일 시점으론 위기 예측 불가 확인.
04 · 군집화
취약형 102개 발견
hub_spoke 창고 67%가 취약 군집 → 레이아웃이 원인인가? 가설 형성.
05 · PSM
결론이 뒤집혔다
운영 조건 통제 후 hub_spoke 효과 소멸(p=0.783). 레이아웃이 아닌 운영이 원인.
결론 수정 3회
처음엔 의심 → PSM으로 확인
hub_spoke 구조가 원인 → 운영이 원인. EDA 오판 → 모델이 발견. 경보 기대 → 구조적 상한 발견.

04

왜 이 방법을 선택했는가

각 방법은 기법을 써보려고 선택한 게 아닙니다. 그 방법이 아니었으면 잘못된 결론에 도달했을 것이기 때문입니다.

왜 GroupKFold를 선택했는가?
✗ 다른 방법 썼다면
일반 KFold → 같은 창고 스냅샷이 학습·검증에 동시 포함 → 데이터 누출 → 성능 과대평가
✓ 이 방법을 선택한 이유
창고 단위로 완전 분리 → 학습에 없던 창고로만 검증 → 실제 배포 환경 시뮬레이션
왜 상관계수 대신 모델 중요도를 봤는가?
✗ 다른 방법 썼다면
상관계수만 → pack_utilization r=0.105 '관계 없음' → 핵심 변수 누락 → 잘못된 분석 방향
✓ 이 방법을 선택한 이유
비선형 U자형 패턴 포착 가능 → 모델 1위 재발견 → 반례 분석과 수렴 → 신뢰도 상승
왜 PSM이 필요했는가?
✗ 다른 방법 썼다면
단순 비교 → hub_spoke +3.69분 유의미 → 레이아웃 개선 추진 → 고비용·잘못된 방향
✓ 이 방법을 선택한 이유
운영 조건 통제 후 비교 → 효과 소멸(p=0.783) → 레이아웃 X, 운영 개선 O → 비용 절감
왜 반례 분석을 별도로 진행했는가?
✗ 다른 방법 썼다면
전체 경향만 → 'idle 높으면 안전' 단순 결론 → idle 정상인데 지연 큰 창고 20개 미발견
✓ 이 방법을 선택한 이유
공통 원인: pack 과포화 → U자형 분석과 수렴 → 두 독립 분석이 같은 결론 → 신뢰도 상승

06

프로젝트 회고

잘 된 점
결론을 세 번 수정하는 분석 태도
EDA 결론을 모델로, 모델 결론을 PSM으로 반복 검증. 가설이 틀렸음을 데이터로 증명한 과정이 분석의 핵심 가치였습니다.
반례 분석으로 신뢰도 상승
pack_utilization U자형 발견을 반례 분석과 독립적으로 검증하여 두 방법이 같은 결론에 도달. 분석 신뢰도를 높이는 방법을 실감했습니다.
방법론 선택에 이유 있는 분석
GroupKFold, PSM, 모델 중요도 각각의 선택 근거를 'X 방법 썼다면 잘못된 결론'으로 명확히 설명할 수 있었습니다.
보완할 점
경보 시스템 대안 부재
Precision ~0.12 상한을 발견하고 '단일 시점의 한계'라고 결론 내렸지만, 연속 상태 감지 방안까지 설계하지 못했습니다.
LSTM 등 시계열 모델로 누적 신호 감지 시스템 설계
실제 운영 데이터와의 간극
시뮬레이션 기반 78% 지연 감소 추정이 실제 운영 환경에서 얼마나 재현될지 검증이 필요합니다.
